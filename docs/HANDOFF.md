# Новое приложение учёта финансов — контекст для продолжения

Документ для передачи в новый чат. Описывает цель, принятые решения, формат исходных данных и план. Вместе с ним приложите файл бэкапа `.mmbak` (SQLite) из папки «Загрузки».

## Цель

Своё Android-приложение учёта личных финансов для семьи (двое: пользователь и жена). Пишется с нуля, НЕ на основе кода Money Manager. От Money Manager берётся только структура (понятия и организация экранов) и совместимость с его форматом бэкапа для разового переноса своих данных.

Три опорные функции:
1. Учёт доходов/расходов/переводов по счетам и категориям, как в Money Manager.
2. **Синхронизация между двумя телефонами через общую папку (Syncthing)** — без своего сервера.
3. **Разбор push-уведомлений банков** (Т-Банк, Сбер, Райффайзен) в транзакции.
4. Веб-версия — не сейчас, но архитектуру закладывать с учётом неё.

## Границы (важно)

- Нельзя копировать/переносить декомпилированный код Money Manager в новое приложение — это чужой код. Можно писать свой с похожими функциями.
- Читать формат `.mmbak` для переноса собственных данных — нормально (совместимость, не копирование).
- Правила разбора уведомлений (`RuBankRules`) — свой код, написан в этом проекте, переносится как есть (см. ниже).

## Технологии (решено)

- **Kotlin + Jetpack Compose**, Material 3. Дизайн современнее Money Manager, но структура экранов как у него (нижние вкладки: операции по дням / календарь / статистика / счета / ещё).
- **Room** (SQLite) — локальная база.
- Архитектура: слоистая (data / domain / ui), однонаправленный поток данных (MVVM/MVI), репозитории, DI (Hilt). Корутины + Flow.
- `minSdk` разумно низкий (напр. 26), `targetSdk` актуальный.
- Деньги хранить в минорных единицах (копейки) как Long, не double.

## Модель синхронизации (решено)

Журнал изменений в общей папке Syncthing. Каждый телефон пишет ТОЛЬКО в свой файл (`<deviceId>.log`), поэтому конфликтов файлов у Syncthing не бывает. Читает файлы всех устройств и применяет чужие изменения.

- У каждой записи (счёт, категория, транзакция): `uid` (UUID), `updatedAt` (мс), флаг `deleted` (мягкое удаление), `deviceId`.
- Разрешение конфликтов: **last-writer-wins** по `updatedAt` на уровне записи.
- Операция — это событие «upsert строки X версии T». При старте и по file-observer читаем журналы, применяем всё с `updatedAt` новее локального.
- Это та же схема, что во встроенной облачной синхронизации Money Manager (дельта-файлы), только транспорт — общая папка вместо их сервера.
- Доступ к папке Syncthing — через SAF (Storage Access Framework), пользователь выбирает папку один раз. Без root.

## Формат исходных данных (.mmbak)

`.mmbak` — это файл SQLite (заголовок `SQLite format 3`), user_version = 19. Открывается напрямую. Таблицы и их роль:

| Таблица | Роль | Записей в примере пользователя |
|---|---|---|
| `ASSETGROUP` | группы счетов (Кошелёк, Карта, Банк…) | 11 |
| `ASSETS` | счета | 19 |
| `ZCATEGORY` | категории и подкатегории | 167 |
| `INOUTCOME` | транзакции | ~9 252 |
| `CURRENCY` | валюты | 2 (RUB осн., USD) |
| `BUDGET`, `BUDGET_AMOUNT` | бюджеты | 1 |
| `REPEATTRANSACTION` | повторяющиеся | 0 |
| `FAVTRANSACTION` | шаблоны | 0 |
| `TAG`, `TX_TAG` | теги | 2 / 0 |
| `MESSAGEMACRO2` | привязка «банк/приложение → счёт» | — |
| `ZETC` | настройки | 20 |

### Ключевые поля для импорта

`ZCATEGORY`: `uid` (TEXT), `NAME`, `TYPE` (0=доход, 1=расход), `pUid` (uid родителя; пусто/`0` у верхних), `ORDERSEQ`, `STATUS` (0=верхняя, 2=подкатегория), `C_IS_DEL` (1=удалена). Иерархия: `pUid` ссылается на `uid` родителя (НЕ на ID). В примере: 5 верхних доходных, 22 расходных, глубина — 2 уровня.

`ASSETGROUP`: `uid`, `ACC_GROUP_NAME`, `TYPE`, `ORDERSEQ`, `IS_DEL`.

`ASSETS`: `uid`, `NIC_NAME` (имя счёта), `groupUid`→ASSETGROUP.uid, `currencyUid`→CURRENCY.uid, `ZDATA` (1 = скрытый счёт), `ORDERSEQ`, карточные поля (`CARD_DAY_FIN`, `CARD_DAY_PAY`, `cardAssetUid` — для кредиток).

`CURRENCY`: `uid` (напр. `RUB_RUB`), `ISO`, `IS_MAIN_CURRENCY`, `RATE`, `SYMBOL`, `DECIMAL_POINT`.

`INOUTCOME` (транзакции): `uid`, `DO_TYPE` (0=доход, 1=расход, 3=перевод-расход, 4=перевод-приход), `ZMONEY` (сумма, строка), `AMOUNT_ACCOUNT`, `ZDATE` (время в мс, строка), `assetUid`→ASSETS.uid, `toAssetUid` (для переводов), `ctgUid`→ZCATEGORY.uid, `ZCONTENT` (заметка), `txUidTrans` (связывает две половины перевода: 3 и 4 с одним `txUidTrans`), `IS_DEL`, `currencyUid`, `UTIME`.

Переводы: одна операция = две строки `INOUTCOME` с общим `txUidTrans` — DO_TYPE 3 (списание с `assetUid`) и DO_TYPE 4 (зачисление на другой счёт). При импорте схлопывать в одну транзакцию-перевод.

## Правила разбора push-уведомлений (свой код, готов)

Файлы `docs/legacy-rules/RuBankRules.java` и тест `docs/legacy-rules/RuBankRulesTest.java` — чистый Java, легко переписать на Kotlin. Логика (проверена на реальных уведомлениях с телефона):

- **Сбер** (`ru.sberbankmobile`): сумма и контрагент в ЗАГОЛОВКЕ, напр. `➕ 10 ₽ по СБП от ИМЯ Ф.`, тело `💳 10 ₽ •• 2824` — это остаток, НЕ сумма. `➕`=доход, `➖`=расход. `•• 2824` — последние 4 цифры карты.
- **Райффайзен** (`ru.raiffeisennews`): заголовок `Заплатили картой *5790`, тело `- 349.00 ₽ в O`Stin. Теперь на карте …`. Знак перед суммой = тип. Есть переводы: `Перевели со счета *5474` / `Пришел перевод на счет *5474`.
- **Т-Банк** (`com.idamob.tinkoff.android`): заголовок — банк второй стороны, тело в 2 строки: `Пополнение на 10 ₽, счет RUB. Имя Ф. / Доступно 10 ₽`. `Пополнение`=доход, `Перевод`=расход.
- Отбрасывать: коды подтверждения («никому не говорите код»), отказы, рекламу.
- Счёт для транзакции ищется по последним 4 цифрам карты в названии/примечании счёта, иначе по названию банка.

Собранные примеры форматов — в `docs/bank-formats.md`.

На Android разбор вешается на штатный `NotificationListenerService` (разрешение «Доступ к уведомлениям»), без обходов чужого кода.

## План реализации

1. **Каркас проекта**: Gradle, Compose, Hilt, Room, структура модулей data/domain/ui.
2. **Модель данных** (Room entities): Currency, AccountGroup, Account, Category (с self-ref parent), Transaction (тип: доход/расход/перевод), плюс sync-поля (uid, updatedAt, deleted, deviceId) на каждой.
3. **Импорт из .mmbak**: открыть как SQLite, прочитать таблицы выше, смаппить в свою модель (схлопнуть переводы по txUidTrans). Разовая операция через выбор файла (SAF).
4. **Основные экраны**: список операций по дням с итогами, добавление/редактирование операции, календарь, месячная статистика (по категориям), список счетов с балансами, управление категориями.
5. **Синхронизация Syncthing**: журнал изменений в SAF-папке, запись в свой файл, чтение чужих, применение по last-writer-wins, наблюдение за изменениями папки.
6. **Разбор уведомлений**: NotificationListenerService + правила RuBankRules (Kotlin) + привязка «банк → счёт» + автодобавление транзакции.
7. **Проверка**: сборка, прогон импорта на реальном бэкапе пользователя (~9 250 операций), сверка сумм и остатков по счетам.

Веб-версия позже: домен и синхронизация не должны зависеть от Android SDK, чтобы логику можно было переиспользовать.
